# 本地插件开发源

默认本机示例：`http://localhost:19337`。实际对外基址统一由 `PLUGIN_SOURCE_PUBLIC_URL` 提供，配置步骤和 Bot 目录登记见 [部署配置](../../pi-im-bot/docs/configuration.md#插件开发源)。

在 Bot 工作台登记目录源后，插件中心 → 发现插件可查看开发包；登记和刷新不会安装或启用插件。后台运行与开机自启由本机部署管理。

## 选型

| 方式 | 适合的职责 | 本地开发时的限制 |
| --- | --- | --- |
| Git | 源码、评审、分支、后续公共发布 | 不宜要求每次测试先提交；当前仓库也未要求已有 HEAD |
| 普通资源目录 | 保存源码、固定构建产物 | 可变目录不能直接当已安装版本，手工维护索引容易与 ZIP 不一致 |
| Bun/Hono 薄服务 | 检查变化、串行构建、提供当前索引和固定包 | 需要受控构建队列与发布一致性，不能每次 GET 都重新打包 |

采用三者分工：Git 管代码，目录管产物，TS 服务生成与现有 Bot 兼容的目录。没有另建包管理协议或 Git 服务器。

```mermaid
flowchart LR
  A[plugins 源码/资源] --> B[指纹扫描与合并]
  B --> C[单个构建进程]
  C --> D[校验固定快照]
  D --> E[按 SHA 保存 ZIP]
  E --> F[原子切换发布记录]
  F --> G[index.json]
  G --> H[Bot 刷新目录]
  H --> I[手动安装/更新]
```

## 使用

```sh
cd pi-im-bot-plugins
./node_modules/.bin/bun run source
```

命令默认以前台方式运行，Ctrl+C 关闭。若已有后台服务，单写入锁会拒绝再启动写入实例；不要同时运行服务和 `--once`。当前后台进程的运行记录在本机验收归档中，日志位于 `.dev-source/service.log`，可通过端口检查确认进程。

```sh
# 服务未启动时只发布变化过的内容
./node_modules/.bin/bun run source --once

# 服务运行时手动强制发布一个开发包
curl -X POST http://127.0.0.1:19337/publish/status
```

工作台 → 插件中心 → 发现插件 → 管理目录源，填写上述 index.json 地址。刷新后可安装系统状态插件。修改源码后开发源自动构建发布，工作台再次刷新显示「更新到此包」。安装/更新保留实例配置，首次安装保持停用，不自动切换 Worker 或发送群消息。

本服务不替代测试：新代码发布到开发源，不等于通过业务测试或正式容器验收。可先在独立 Mock Bot 验证，再手动更新正式实例。

## 变化检测与资源

- 每秒扫描维护中的插件目录，文件未变时复用摘要缓存；采用轮询以避免递归 watch 在不同系统、node_modules 与生成目录上的行为差异。
- 750 ms 合并改动，连续变更最长合并 3 秒；任意时刻最多一个构建进程。
- 忽略 node_modules、dist、API-SNAPSHOT.json、生成的 renderer.wasm 和隐藏文件，避免构建触发自身。
- 代码、schema、README/许可/资源、bun.lock、类型/构建设置以及已同步 API 摘要参与指纹。
- Bot API 文档过期会使构建失败，上一份包继续可用。开发者先运行 docs:sync，不由服务悄悄修改知识基线。
- 构建中源码又变了，丢弃这份候选并合并后续构建，不发布混合内容。
- 构建进程最长 60 秒，错误输出截断；默认保存包的硬预算 512 MiB，最多 1024 次发布记录，达到上限拒绝新发布并保留旧源。本期没有自动删除历史包的 GC。

只调用本工作区受维护的 build 脚本，不执行插件入口、远端 Git 拉取或 npm install。依赖变化先由开发者明确安装。环境只传构建所需路径，不复制 Bot 上游凭据。

## 版本与发布一致性

```text
plugins/status/                    作者源码，version 保持 0.1.0
.dev-source/
  state.json                       已提交的发布记录/序号
  packages/system-status/<SHA>.zip  不可变包
  staging/                         临时固定代码快照
  runtime-owner.sqlite             OS 持有的单写入锁
  service.log                      本机后台部署日志
```

开发版在包副本中生成 `0.1.0-dev.N`，不回写原 manifest；已有预发布后缀时追加 `.dev.N`。序号只在成功发布时前进，重启继续原记录。

先校验包、写 ZIP 并同步落盘，再原子提交 state；HTTP 读取已提交状态动态返回 index。ZIP URL 与 SHA 绑定，永不覆盖旧 URL，旧目录缓存和在途下载不会突然拿到另一份代码。旧源码包只被作为文件导出，不直接挂载为 Bot 的可变安装目录。

Bot 安装时验证目录中的 SHA/包 ID/版本，并记录源 ZIP 摘要。目录中同一插件即使语义版本相同，只要包摘要不同也能提示更新；仅比较 installedId 会漏掉开发更新，因此框架同时修正了该入口。

构建错误、源码临时缺少 manifest、或发布容量不足时保留上一份目录条目。插件目录真正删除时从当前索引移除，但旧 ZIP 保留，已安装代码不受影响。

## HTTP 接口

| 接口 | 作用 |
| --- | --- |
| GET / | 当前插件、构建状态、最新版本与错误摘要 |
| GET /health | 服务存活 |
| GET /index.json | 现有 Bot 静态目录协议，no-store |
| GET /status | 构建队列、监听、历史数量与最近结果 |
| POST /publish/:目录名 | 只接受当前工作区已登记目录，排队并返回 202 |
| GET /packages/:插件ID/:SHA.zip | 已发布固定包，长期 immutable 缓存 |

接口不提供任意文件读取、上传源码、宿主命令、任意目录构建或自动安装到 Bot。家用可信 LAN 直接访问，不额外设置本地口令。

启动设置统一见 [部署配置](../../pi-im-bot/docs/configuration.md#插件开发源) 及仓库 `.env.example`。Bot 在 Docker 时仍应使用 LAN 可达地址，不能把容器内 127.0.0.1 当成本机源服务。

## 后续扩展

按需增加 dev/stable 双通道、历史清理、构建摘要与来源 commit 展示。GitHub/CI 发布仍可导出同一索引与 ZIP；无需把 Bot 和本地源服务耦合成一个进程。自动安装只考虑显式指定的开发 Mock 实例，本期没有默认自动更新正式群的行为。
