# 迁移工作约定

1. 每个插件单独放 `plugins/<id>/`，先记录当前部署的入口、schema、metadata 和逐文件摘要；不要把全部已安装目录都当作启用需求。
2. 在 MIGRATION.md 写清命令/工具/被动行为/异步/配置/数据和宿主依赖，并标出已完成与差异。
3. 先检查 Bot 能力手册。缺少能力时扩展受管接口，不把原 AstrBot Context、平台对象或宿主路径塞进 Worker。
4. 同一个操作复用指令和工具；Core 保留指令不可覆盖。按群共享状态与配置，触发人的身份只约束调用权限。
5. 业务代码、解析、渲染与格式化拆分；import 不发请求、不开定时器。长任务用 Job，延后动作交给持久机制。
6. 用临时目录和自编替身验证，再交给独立应用 Mock 验收。替身不是真实沙箱，禁止用它执行任意下载插件。
7. 发布前 build/check/test/pack 并记录包摘要；新增二进制/WASM/字体必须随包和许可声明一起声明。
8. 默认关闭是新配置的默认值，当前部署状态以 Bot 在线诊断为准。2026-11-12 部署记录和 2026-11-13 只读观察均确认 enabled:true。启停、容器变更、旧数据迁移和真实群测试不包含在普通源码验证中。
